# 前端 NLHE 加注限制

依据 [Poker TDA 2026 官方规则](https://www.pokertda.com/view-poker-tda-rules/)第 45、49 条，在活动页面 `p.html` 实现，未修改后端。卡牌、筹码、轮到谁行动仍由收到的完整快照更新。

## 最小加注与加注权

`src/poker-betting.js` 从每次确认的快照记录当前最高下注、最大的完整下注/加注增量，以及每位玩家上次行动时响应的最高下注额。新手、新下注轮、换房间/用户分别隔离记录。

- 本轮起点为大盲额，翻牌前盲注投入不算主动行动。
- 完整加注下限为当前最高下注加完整增量。例如 10/20，raise60、all-in80 后，未行动者至少加到120。
- 只有单次完整下注/加注更新完整增量；多个短全下的累计不能成为新的最小加注增量。
- 玩家尚未行动，或者当前最高下注减去其上次响应额达到完整增量，才有加注权。过牌后面对首次下注仍保留加注权。
- 已下注玩家面对单次不足完整加注的全下，只能跟注或弃牌。即使加注部分超过50%，也不重开 NLHE 加注权。
- 多个短全下累计足够时按每个人分别判断；100、all-in125、call125、all-in200 后，下注100的人可加，跟过125的人只面对75，不能加。
- 翻牌后首次短全下小于大盲时，后续允许补成大盲额的完整下注。仅剩一位未全下玩家时不能向全下者继续加注。

页面动作明确是“加注”，不会模拟实体筹码静默下注的50%补足/跟注判定。普通不足最小加注的金额直接禁止；真实筹码上限不足下限时只允许短码全下，且必须有加注权。全下跟注不足时显示实际需要投入的剩余筹码。

## 断线与刷新

快照没有提供当前手的完整行动流水，也没有公开每人 `acted/lastResponded`、完整加注增量。当前下注总额无法唯一反推出这些信息。因此前端连续观察快照，并在当前标签页的 `sessionStorage` 保存一份最小记录，不保存底牌、凭证。

刷新/重连时匹配房间、用户、手牌和下注轮恢复记录；重复快照不会重置行动起点。存储不可用时仍可在内存跟踪。首次在已经下注的轮次进入、或者快照跳过了无法还原的多个动作，前端禁用加注并说明“本轮行动记录不完整”，仍允许正常过牌/跟注/弃牌。下一下注轮/新手从起点恢复。不会根据最终下注额或服务端 `canRaise/minRaiseTo` 猜测缺失历史。

## 验证

运行 `npm test`。`tests/poker-betting.test.js` 覆盖完整增量、短全下、累计重开、个人行动起点、BB保留选项、差1/刚好完整、短全下上限、首次短下注、重复快照、重连/缺失历史以及数值校验。页面集成测试验证按钮/滑杆/全下/提交拦截以及实际 ACTION 金额。
